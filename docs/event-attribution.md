# FedWatch 重大变动归因计划

## 当前目标
把全历史所有「最大概率区间概率日环比绝对值 ≥ 8pp」的交易日都补上原因，写入 `data/events.csv`，让看板光环覆盖完整历史。

这是**叙事归档**，不是因果模型：`analyze_changes.py` 只负责找 ≥8pp 的日子；原因优先对照窗口内的财经新闻，再用官方数据/讲话核验后写入。找不到同日可核对的稿，就标「待核实」，不硬安因果。

本文件是本项目的 **living plan**：归因口径、完成状态、待核实清单和验收都写在这里。部署细节见 `docs/deployment.md`。

## 焦点会议口径（2026-09-17 起，默认）

**检测范围收窄到「最近一场尚未开完的 FOMC」。**

- 焦点会议 = 该快照里最早的、`meeting_date >= 快照日` 的会议；全部已过期则取最后一个。
  会议开完当天仍算焦点（决议当天才公布），到下一个快照才滚走。
- 只比对**同一场会议**在两个相邻快照的值；会议刚滚进来的那一次不比对（没有基线）。
- `analyze_changes.py --focus nearest`（默认）／`--focus all` 回退到旧的全会议口径。

为什么收窄（这三个理由都能用数据验证）：

1. **远端是薄流动性形态，不是宏观重定价。** 第 7 近及以后的会议中位 |Δ| = 0.00pp
   （常常根本没报价），一跳就是 40–70pp。
2. **会议开完会让整表概率被重新归一化**，同一快照里多场会议齐刷刷跳同样的百分点数。
   实测 2026-09-16 有五场会议**完全同幅 +14.00pp** —— 那是一个机制性事件，不是五个新闻事件。
3. **实测对比**：全会议口径全年 41 次触发；焦点口径 **33 次**，其中换桶日 8 次
   （2026-09-18 换桶日改用「同一区间」幅度后，从 29 次修正为 33 次，见下一节）。
   触发量下来了，媒体命中率上去了。

**代价与边界**：焦点口径只看一条曲线，远端会议的异常波动不再进入归因队列。
这是有意为之——远端那类跳变（如「0.00 → 65.91」）本来就该归因为数据/流动性问题，
归因队列里标注它的收益低于它带来的误判风险。

**`2026-09-17` 是焦点口径下第一条归因**：焦点从 2026-09-16 滚到 2026-10-28。
该日读数后来被 09-18 05:30 的收盘定格覆盖（375-400 60.00% → 400-425 53.14%，
按同一区间 375-400 为 −13.14pp）。原因见 `data/events.csv`。

## 「一天一个点」与归因绑定（2026-09-18，事故修复）

**同一个美东交易日会有多条读数，图每天只画一个点。**

- 每天早晨 05:30 采到的**收盘定格**（`time_basis=page_asof`）胜出，
  前一天 10:00 采的**盘中读数**（`legacy_intraday`）被顶掉、不再出现在图上。
- 裁决规则集中在 `snapshot_view.displayed_by_day()`：
  **收盘定格 > 结算导出 > 盘中读数**，同口径取最早。
  `build_report.py`（画点）与 `analyze_changes.py`（检测）**共用这一份**，不允许各写一套。

### 事故：2026-09-17 的光环不见了

- 归因写在 `snapshot_cn = 2026-09-17 10:00:00`（盘中读数）。
- 09-18 早晨的收盘定格 `2026-09-18 05:30:00`（`us_trade_date=2026-09-17`）胜出，
  图上那个点变成了它；旧的 `snapshot_cn` 不再出现在任何曲线上。
- 光环与悬窗都是按 `snapshot_cn` **逐字符匹配** `events.csv` 的 → 匹配不上 → **静默消失**。
  页面本身不报错；`analyze_changes` 也照样说「已标注」（它当时按快照日期前缀匹配）。

### 两条修法

1. **归因按美东交易日绑定**：`snapshot_view.remap_events_to_points()` 生成图表数据时，
   把每条归因重挂到「同一天真正出图的那个点」上。
   因此 `events.csv` 的 `snapshot_cn` 写哪天都行 —— 口径再切换也不会掉。
2. **检测端与展示端共用选点规则**：检测按「出图日」序列逐日比对，
   不再按原始快照序列（否则会把同一天的两次读数当成两天）。
   「已标注」判定也改为按美东交易日匹配。

### 换桶日的幅度必须换口径

最大概率桶换桶时，`max_range_pct` 前后是**两个不同结果**的概率，直接相减没有意义：

| 日期 | 图上读数（最大桶） | 同一区间实际搬家 |
|---|---|---|
| 2026-07-15 | +1.49pp（看着像没事） | 「维持」350-375 **+9.62pp** |
| 2026-08-07 | +0.57pp（看着像没事） | 「维持」350-375 **+10.57pp** |
| 2026-08-28 | −7.57pp | 「加息 25bp」375-400 **+21.57pp** |
| 2026-09-17 | −6.86pp | 「加 25bp」375-400 **−13.14pp** |

因此 `analyze_changes.measure_change()`：**换桶日取「同一绝对区间」里 |Δ| 最大者作为幅度**，
方向仍沿用图上最大桶的涨跌（保证光环颜色与读者看到的线段一致）。
这一条把 4 天此前被漏掉的真实大变动（06-18 / 07-15 / 08-07 / 08-28）找了回来。

### 单位陷阱（务必记住）

`fedwatch_probabilities.csv` 里 **`aggregated_ranges` 这一列混用两套单位**：
历史导出段是 **0-1 小数**，实时段是 **0-100 百分数**，直接相减会把 24pp 算成 0.24。
**读分布一律用 `range_XXX_YYY_pct` 列**（恒为百分数）。
2026-09-18 曾因这个坑把 03-12 / 09-03 / 09-04 三天误判为「不重大」。

### 别再用 snapshot_cn 做事件匹配

`events.csv` 的 `snapshot_cn` 现在只是**归档键**（写哪天都行）；
任何「读事件 → 关联到图上点」的逻辑都必须走美东交易日。
`site_seo.py` 的分析页本来就是按交易日显示（`us_day_map`），无需改动。

## 时区与对照窗口

两套快照不要混用。

**历史回填（3–6 月，`snapshot_cn=YYYY-MM-DD 10:00:00`）**
- `10:00:00` **只是日期标签**，不是北京 10:00 采集时刻。
- 来源是 FedWatch AllMeetings 回填，底层是 **美国交易日 EOD**。
- 当日 08:30 ET 数据 **和** 当日下午 FOMC 都进 **同日** snapshot。
- **不要**用 live `run_daily.sh` 的「北京 10:00 = 上一美国交易日」去解释 3–6 月。

**Live 采集（8 月之后）**
- 才是北京时间：`2026-09-11 11:41:00`（实际抓取于 9/12 周六）、`2026-09-14 10:03:00`。
- 美国当日 08:30 ET 的 CPI / 非农 / PPI，通常要到 **次日** 北京 10:00 快照才进入序列。
- 周一 live 快照要覆盖上周五尾盘 + 周末新闻。`09-14` 是周一北京 10:03 ≈ 周日 22:03 EDT，利率期货周日晚复盘后约 4 小时。

对照窗口：`prev_snapshot` 之后 → 本快照。只把这个窗口里的数据/讲话/地缘事件当作候选原因。

## 资料与检索策略（新闻优先）
1. **先搜新闻报道**：按日期、`FedWatch`、`rate hike odds`、`Treasury yields`、`Fed`、关键数据名称检索 Reuters、Bloomberg、WSJ、CNBC、MarketWatch 等当天报道。
2. **再核对官方源**：BLS 数据稿、美联储声明/讲话、EIA 等，确认数字和发布时间。
3. **最后看概率曲线**：报道中的方向必须与桶位移一致。油价涨却走鸽、油价跌却走 hawk，就标「待核实」，不要硬写。

每个日期至少 1 个 `url`。连续反向日若新闻也没有明确宏观解释，写成回吐/波动，不另编故事（对齐 `04-30`、`09-14`）。

## `events.csv` 写法
- `summary`：一句话，适合做弹窗标题
- `direction`：按最大变动会议的 `max_range_pct` 实际涨跌填写：上涨为 hawk，下降为 dove；不要用宏观 hawkish/dovish 叙事替代图上方向
- `text`：必须包含变动最大的会议、区间是否换档、pp 变化，以及 1–3 个同窗口候选事件
- 文体对齐 `2026-08-04`、`2026-09-11`：先事件，后点名最大会议与 pp
- `url`：**可挂多条来源，用 `|` 分隔**。单条渲染为「🔗 查看来源」，多条渲染为「🔗 来源1 🔗 来源2 …」。
  建议 3–4 条：官方一手 + 1–2 条权威媒体 + 可选 1 条中文财经。再多用户会无从选择。
  下游 `site_seo.py` 会自动按同样规则拆成多个 `<a>`，不会把 `|` 串成一个坏链接。
- `text` 里的 `\n` 会被渲染成 `<br>`（`build_report.py` 的 tooltip 与分段）。建议 4–6 段、总长不超过约 750 字，
  超出后弹窗需要滚 3 屏以上，反而没人读完。

## 媒体归因怎么写（2026-09-17 二次修订：对号入座版）

**核心要求：每条归因回答"这个日期的窗口里到底发生了什么"，不写背景综述。**
09-17 第一版写成了「为什么美联储要加息」（CPI/就业/油价背景铺陈），被指出是笼统分析——
用户要的是：这一天是通胀数据超预期、就业数据超预期、还是官员讲话，对号入座。

### 定点归因三步法
1. **换算美东交易日**：北京 D 10:00 快照窗口 = 美东 D−1 全天（约 22:00 截止）。所有"当日"以美东为准。
2. **查当日日历**：数据发布（CPI/PCE/非农/JOLTS）、FOMC/纪要、噤声期（会前第二周六起）、
   官员讲话、国债拍卖。**先排除再检索**——日历上是空的就别硬找，写明"无当日触发"。
   ⚠️ 数据日历可能改期（如 2 月 PCE 因停摆从 3/27 延到 4/9），必须用 BLS/BEA 官方日程核对。
3. **检索落点**：找到单一触发 → 写【当日触发】+ 来源；找不到 → 写【机制】给出最合理候选 + 【排除项】
   列出已排除的假设 + 明确标注置信度。不硬安因果。

### 正文段落结构（对号入座版）
| 段 | 内容 | 要点 |
|---|---|---|
| 【当日触发】 | 窗口内发生的具体事件 | 是什么、几点、谁说的/什么数据；没有就直说"无单一触发" |
| 【机制】/【更正】 | 事件如何传导到桶位移 | 或：发现旧记录有误时的更正说明 |
| 【排除项】 | 已排除的假设及理由 | 如"PCE 已延期至 4/9，本条与 PCE 无关"——证明检索过，不是漏了 |
| 【口径】 | 图上方向 vs 宏观方向 | 桶概率降记 dove 但宏观可能鹰派，勿混 |

### 与旧写法的区别
- ❌ 旧：【媒体归因】罗列通胀/就业/油价三条背景动因——那是"为什么这个月转向"，不是"为什么这一天跳了"。
- ✅ 新：窗口内只有一个事件就只写那一个；背景动因只有当它在**本窗口内**成为触发时才写。
- 「待核实」不再作为长期状态：要么找到触发（写明来源），要么写明"无当日触发 + 机制 + 置信度"。

反面教材（不要这样写）：「机构普遍认为 X 因素导致 Y」——没有机构名、没有数字、无法复核，等于没归因。

## 改图表 JS 时的坑（务必先读）

`build_report.py` 里的图表 JS 位于 **Python 模板字符串**内，新加的 JS 代码会被 Python 先做一次转义：

- 正则里的换行必须写 `\\n`。直接写 `\n` 会被 Python 解释成真实换行，
  生成页里就会出现**跨行的正则字面量** → 整段内联脚本 SyntaxError → 图表交互（tooltip、光环、滑块）**全部静默失效**，
  而页面看上去完全正常。这个故障一次性让浮窗完全不响应，排查了两轮才定位。
- 同理注意 `\d`、`\s`、`\b` 等转义序列（`\b` 会变成退格符）。
- **每次改完必须校验生成页**：
